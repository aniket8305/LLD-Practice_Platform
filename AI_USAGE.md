# AI Usage

AI was used as a development assistant during the implementation of the LLD Practice Platform. It was mainly used for small design suggestions, UI improvements, debugging, and testing support. Final decisions were reviewed and adapted based on the assignment requirements and the project's scope.

## 1. UI Copy and User Experience

**AI suggested:** Improvements to button labels, headings, loading messages, and feedback wording.

**Accepted:** Several suggestions were adopted with minor edits.

**Why:** The suggestions helped make the interface clearer and more consistent without changing the functionality.

---

## 2. Error and Empty States

**AI suggested:** More useful messages for cases such as failed evaluation, empty submissions, and loading states.

**Accepted:** Relevant suggestions were incorporated.

**Why:** Clear error messages make it easier for learners to understand what happened and what they can do next.

---

## 3. Code Review and Debugging

**AI suggested:** Small code improvements and fixes after reviewing implementation details.

**Accepted:** Only changes that were relevant to the existing implementation were applied.

**Rejected:** Suggestions that introduced unnecessary abstractions or changed working parts of the application were not used.

**Why:** The goal was to improve reliability without expanding the scope or unnecessarily refactoring working code.

---

## 4. Testing and Edge Cases

**AI suggested:** Additional edge cases to consider, such as empty submissions, duplicate actions, evaluation failures, and retry behavior.

**Accepted:** Relevant cases were added to the testing process.

**Why:** These cases helped verify that the practice flow behaves correctly when something goes wrong.

---

## 5. Documentation Review

**AI suggested:** Improvements to the structure and clarity of the README and supporting documentation.

**Accepted:** The documentation was reorganized and wording was refined where useful.

**Why:** This made the architecture, setup process, design decisions, and project scope easier to understand for someone reviewing the project.

---

## Summary

AI was used primarily as a **supporting development and review tool** rather than as a replacement for engineering decisions.

The final implementation and scope were determined based on the assignment requirements, practical constraints, and the project's intended MVP.
